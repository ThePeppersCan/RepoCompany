ROOT CAUSE
The V2 engine sends a `repo-sports-v2-rotation-complete` message at full time.

The parent previously accepted that message ONLY when:
  repoV2LiveIsHost === true

If the iframe finished the match a fraction before this browser acquired the
global host lease, the valid final result was silently discarded.

The engine then set:
  rotationQueued = true

and never announced completion again.

RESULT:

  SYNCING NEXT LIVE MATCH...
  forever

FIX 1 — QUEUE BEFORE HOST
The parent now passes EVERY valid completion message from the visible/headless
Repo Sports iframe into repoV2CompleteRotation().

If the browser is not host yet:
- the result is stored as repoV2PendingCompletion
- retry timer starts
- when the host heartbeat grants the lease, the same result is submitted

FIX 2 — PERIODIC RE-ANNOUNCEMENT
The live engine now re-sends the completed result roughly every 2 seconds while
the same finished match serial remains open.

This is safe because the server already uses:
- current match_serial
- repo_sports_recorded_matches primary key
to prevent double-counting.
