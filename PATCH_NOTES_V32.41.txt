VELMORA DRAGONBOUND — V32.41 ONE-AND-DONE ACCOUNT LOCK

LIVE DATABASE
- The Dragonbound account system has been added to the live Velmora Supabase project.
- Existing server-side Dragonbound egg/dragon ownership was cleared for everybody.
- Verified immediately after the reset: 0 locked eggs and 0 owned dragons.
- Previous test ownership mostly lived in browser localStorage, so V32.41 performs a one-time local Dragonbound ownership reset the first time each browser loads this build.
- Starter-house choice is deliberately not removed by the ownership reset.

NORMAL ACCOUNTS
- The first egg successfully rolled is now atomically locked to the signed-in account on the server.
- Refreshing, changing browser-side values or reopening Bonnie does not provide another legitimate roll.
- Once an egg is locked, the adoption UI shows the account's locked egg instead of allowing more rerolls.
- Once the dragon is hatched/named, that breed is server-validated against the account's locked egg.
- A normal account cannot obtain another egg/dragon for now. Future upgrades can extend this system later.

ADMIN TEST ACCOUNT
- Username "Admin" is detected case-insensitively by the server and client.
- Admin keeps unlimited egg rerolls for testing.
- Admin can repeatedly run the delivery, basket opening, hatch and naming flow.
- No generic admin/site testing functionality is removed by this reset.

STARTER HOUSES
- Starter houses remain free.
- Players can swap between the five starter houses whenever they want, even after getting their dragon.
- Server-side house selection only accepts the five starter-home IDs.
- Larger/non-starter properties remain unavailable; there is no live house purchasing flow enabled here.
- Existing-home players receiving their new V32.41 egg are sent back to their current starter home for Doppy delivery rather than being forced through the first-time estate-agent tutorial again.

ACCOUNT ISOLATION
- Dragonbound local ownership, selected starter home and baby movement data are now scoped by account username.
- Multiple accounts using the same browser no longer share/overwrite the same Dragonbound local state.

SECURITY
- Authenticated clients have SELECT-only access to their own Dragonbound profile row through RLS.
- Egg claims, starter-house changes and dragon naming are handled through vetted SECURITY DEFINER RPCs.
- Direct authenticated INSERT/UPDATE/DELETE/TRUNCATE access to the Dragonbound profile table is not granted.
