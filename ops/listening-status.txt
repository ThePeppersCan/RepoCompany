Wibs listening status

Enable: Wibs > profile settings cog > Listening activity > Share Reparty listening.
The member list and profile card show currently playing Reparty media. Images are
loaded directly from YouTube/Suno/Spotify. No audio or artwork bytes are uploaded.
Only two bounded current metadata records per account can exist (one per source),
plus two preference flags; there is no listening history. Typical metadata is well
under 1 KB per source, excluding database/index overhead. Old records are replaced;
an expired record cannot be displayed. Explicit stop removes its track metadata.
Clock animation is local. Stable playback sends a heartbeat about every 30 seconds;
changes/pauses send bounded updates. Expiration is 90 seconds or the track end,
whichever is sooner. API/auth requests and small database operations still count.

Privacy: sharing defaults off. Invisible mode and existing private-profile/friend
and block rules apply. Reparty takes priority when both sources are playing.
Suno's web embed does not expose precise playback timing: the card labels the room
timer approximate. YouTube uses the actual local player's position and play state.
Mute, zero volume, personal pause and leaving clear Reparty sharing.

Apply dashboard-listening-schema.sql to the target DASHBOARD_DB before deploying.
No Supabase migration, music storage bucket or new paid service is needed.
Build with node tools/build-dashboard.cjs --production --preserve-game-integrations
for this web-only change; run the repository's deployment-base check before release.

Optional Spotify setup (disabled until configured)
1. Register a Spotify Web API app in https://developer.spotify.com/dashboard.
2. Add the exact redirect URI https://repocompany.uk/spotify-connect.html.
   Register any other actual browser origin separately if it must be supported.
3. Set SPOTIFY_CLIENT_ID to the app's public client ID in the Cloudflare Pages
   production environment. No client secret is used: this is authorization-code
   PKCE with only user-read-currently-playing permission.
4. Add approved test accounts in Spotify's app user management, then redeploy and
   use Connect Spotify from Listening activity. The connection lives in that tab's
   session storage, clears on account change/disconnect, and is not stored on the
   RepoCompany server. RepoCompany must remain open to share Spotify activity.
5. Validate with a real Spotify account before treating Spotify as live-tested.

As checked 18 October 2026, a development app requires its owner to have Premium
and supports up to five allowlisted users. Wider access requires Spotify approval;
current partner criteria include a registered organization and 250,000 monthly
active users. This feature does not remove those requirements.
https://developer.spotify.com/documentation/web-api/concepts/quota-modes
