DRAGONBOUND SOCIAL + CALENDAR SYSTEM V33.81
IMPLEMENTATION REFERENCE

1. CALENDAR MODEL
-----------------
Time zone: Europe/London.
Calendar length: 31 days.
One fictional day: one real UK date.
Fixed epoch: 2026-07-30 = Velmoran Day 1.

Calculation:
  UK date -> UTC date-only serial
  deltaDays = floor((dateSerial - epochSerial) / 86,400,000)
  day = positiveModulo(deltaDays, 31) + 1
  cycle = floor(deltaDays / 31) + 1

The accelerated house clock is NOT read by this system.
The current day is therefore shared across accounts and cannot drift due to local counters.
A single scheduled timeout refreshes at the next observed Europe/London date boundary.

2. EVENT REGISTRY
-----------------
Events live in the data-driven EVENTS registry in dragonbound-calendar-social.js.
Each event contains:
  day
  id
  name
  importance
  icon path
  description
  accent
  atmosphere key
  behaviourBias
  furnitureBias

This is the extension point for future Bonnie/Bolt/shop/raceway/event dialogue hooks.

3. EVENT SPRITES
----------------
All sprites are separate transparent PNG assets under:
  assets/dragonbound/calendar/

They use crisp-edged shapes and a consistent muted Velmoran palette. Keeping them separate avoids shipping a large atlas merely to add or replace one festival later.

4. FESTIVAL BEHAVIOUR
---------------------
BabyDragonActor.scoreAction() calls:
  DragonboundCalendar.actionBias(action, actor)

BabyDragonActor.scoreFurnitureTags() calls:
  DragonboundCalendar.furnitureBias(tags, meta, actor)

Both hooks are optional-safe. If the module is unavailable the base V33.80 score remains unchanged.
Event values are intentionally small. Existing care priority/need thresholds remain authoritative.

6. RELATIONSHIP DIMENSIONS
--------------------------
Internal rows can contain:
  familiarity
  trust
  affection
  comfort
  playAffinity
  curiosity
  tolerance
  protectiveness
  jealousy

Raw values are not presented to normal players.
Player-facing stages are derived from the combined evidence and can become:
  Noticed
  Curious
  Familiar
  Friendly
  Playmate
  Close Friend
  Deeply Bonded
  Favourite Companion

Relationship growth is incremental and event-driven. There is no rapid absence decay.

7. PERSONALITY INTERACTION
--------------------------
V33.80 traits modify the rate/style of social moments rather than replacing relationship evidence.
Examples:
  Affectionate -> slightly stronger affection/comfort gains.
  Shy -> slower initial familiarity/curiosity but trust can still grow.
  Independent -> slightly lower affection gain without blocking closeness.
  Curious/Explorer -> stronger curiosity.
  Playful/Hyper -> stronger play affinity.
  Sleepy/Quiet Companion -> shared rest means more.

Personality remains WHO the dragon is.
The social row remains HOW this dragon feels about one specific household companion.

8. BEDROOM PET BRIDGE
---------------------
The system reads the public VelmoraBedroom API only:
  VelmoraBedroom.petState()
  VelmoraBedroom.pets

The current bedroom pet's breed, type and custom name are used in the Bonds journal.
No bedroom.js mutation was required.

Invited household visits use existing pet frame paths:
  assets/bedroom/pets/<breed>/idle-0..3.png
  assets/bedroom/pets/<breed>/walk-0..3.png
  assets/bedroom/pets/<breed>/sleep-0..3.png

The visitor uses DragonboundBabyEngine navigation helpers for legal points/pathing. It is a temporary social visitor, not a second persistent bedroom simulation.

9. SOCIAL MOMENT AUTHENTICITY
-----------------------------
Relationship evidence is generated from actual visitor/keeper events:
  keeper_pet
  keeper_greeting
  visit
  near
  follow
  play
  shared_rest
  window
  protective

Repeated proximity has cooldowns, preventing one visit from instantly manufacturing a best friend.
Notable social history is bounded.

The Book does NOT say that a shared nap happened unless close proximity and an actual rest/sleep context were detected.

10. FESTIVAL MEMORY AUTHENTICITY
--------------------------------
BabyDragonActor.noteUniverseActivity() emits a lightweight custom event containing the already-recorded V33.80 activity kind.
The Calendar module listens to this event only while relevant.

During a real festival session it counts real activity categories. A representative event memory can be created only after at least one meaningful observed activity. No event memory is created merely because the player opened the site on an event day.

Admin preview never writes festival history.

11. BOOK / UI ORGANISATION
--------------------------
Keeper Journal tabs:
  Nature
  Habits
  Bonds
  Life
  Calendar
  Scrapbook

Desktop uses a restrained six-tab ink navigation strip.
Narrow layouts use two rows of three without shrinking copy into unreadable text.

Bonds uses parchment rows, real pet portrait sprite, ink descriptor and short observation.
Calendar uses a compact today sheet plus upcoming/memory columns.
The full calendar is an independent parchment almanac overlay with 31 cells and a detail page.

12. HOUSE ATMOSPHERE
--------------------
Festival decorations are CSS/DOM layers only. They do not replace house art.
No festival RAF exists.
Animations are paused when the house is covered by the Book, Travel or full Calendar and the layer is removed on house close.

13. HATCH ANNIVERSARY
---------------------
The existing hatch timestamp is compared by Europe/London month/day. If today matches, the Calendar Book page shows a small Hatch Day Anniversary note.
This does NOT enable aging and does not alter growth art.
