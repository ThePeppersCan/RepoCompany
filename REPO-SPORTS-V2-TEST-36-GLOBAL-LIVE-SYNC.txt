REPO SPORTS V2 TEST 36 — GLOBAL LIVE BROADCAST SYNCHRONISATION

MANDATORY FIRST STEP
Run repo-sports-v2-global-live-sync.sql ONCE in Supabase SQL Editor before copying the web files.

WHAT TEST 36 CHANGES
- One global Repo Sports V2 match exists for everyone.
- Fixture, arena, teams, player assignment and simulation seed are derived from the server match_serial.
- Any viewer opening V2 joins the current match at its current shared point.
- The engine uses a fixed 30 Hz simulation step, so the same seed + same global elapsed time produces the same passes, tackles, shots, goals, fouls, VAR, celebrations, replays and penalty shootout.
- Local sessionStorage/Date.now rotation has been removed.
- There is no per-browser next-match offset anymore.

NO VIEWERS = NO GAMES RUN
This deliberately mirrors the existing RepoSports background-host model:
- Every open RepoCompany browser sends a five-second V2 background heartbeat.
- One browser holds a short server lease and advances the global V2 active clock.
- That browser runs a hidden authoritative V2 simulation so rotations still happen even if it is on another page rather than watching the TV.
- If the last browser leaves the website, all heartbeats disappear.
- The Supabase clock freezes.
- If someone returns hours later, the same match resumes from the frozen point; the hours offline are NOT added.

HOST FAILOVER
- Host lease is 12 seconds.
- If the host browser closes while somebody else remains on the site, another browser takes over automatically after the short lease expires.
- Rotation completion is idempotent and only the active lease holder can advance to the next global match.

GLOBAL ROTATION
- 30 second prematch
- 4:30 regulation
- penalty shootout on a draw
- 30 second full-time screen
- then ONE global next match for everybody
