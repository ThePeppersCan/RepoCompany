V32.69 — Dragonbound Furniture Purchase Stability + Click-to-Interact
================================================================

FURNITURE SHOP CRASH / SITE PERFORMANCE
- Verified the live dragonbound_purchase_furniture RPC itself works correctly with the Kordesh Stone Feeding Altar in a rolled-back authenticated transaction.
- Fixed the frontend favourite-card cache so a valid 'no favourite' result is cached instead of being treated as 'not loaded'.
- Fixed Repo Passport favourite-card hydration repeatedly refetching and re-rendering when an account has no favourite card.
- Removed the V32.67 favourite-card MutationObserver from the entire document body; it now watches only the binder dialog's open/page attributes.
- Furniture purchase now has an in-flight guard, normalises the RPC receipt, updates only the shop grid/inspector instead of rebuilding the whole shop shell, and logs/recovers cleanly on an actual RPC error.

CLICK-TO-INTERACT FURNITURE
- Outside Build Mode, placed furniture is now clickable.
- Clicking a furnishing explicitly commands the player's baby dragon to use that exact placed object.
- The command overrides the dragon's current idle/rest/sleep choice and paths to a safe interaction point beside the object.
- If the object is on the other floor, the dragon paths to the correct staircase, visibly climbs it, reaches the target floor, then continues to the furnishing.
- A dragon already halfway up/down the stairs is never snapped off the staircase; the interaction command queues until it reaches the landing.
- Existing semantic furniture behaviours are reused: food, drink, wash, sand-bathe, groom, sleep, rest, play, puzzle, train, roar, fire practice, scratch, dig, climb, hide, bask, window-watch, read, mirror, sniff, toilet and inspect.
- Added subtle hover feedback to clickable furniture in normal play.
- Build Mode editing/placement clicks keep their existing behaviour.
