REPO SPORTS WORLD CUP — V38.3 GAMEPLAY MODULE LOAD FIX

Modified files only:
- index.html
- world-cup-quidditch-v1.js

ROOT CAUSE
V38 introduced dynamic venue commentary using fixtureVenue() while the
JavaScript module itself was still being initialised.

fixtureVenue() reads state.fixture, but state had not been created yet.
This caused:
ReferenceError: Cannot access 'state' before initialization

The entire gameplay JS stopped executing before:
window.RepoSportsWorldCupGameplay
could be installed, which is why every lobby reported:
"World Cup gameplay module did not load."

FIX
- Halftime/full-time dynamic venue lines are now deferred until the
  commentary is actually used during a match.
- The module now fully executes and installs RepoSportsWorldCupGameplay.
- JS script cache version bumped to v38-3-loadfix.

VALIDATION
- JavaScript syntax check passed.
- Full mocked browser module-load test passed.
- Confirmed window.RepoSportsWorldCupGameplay is created.

No assets are included.
