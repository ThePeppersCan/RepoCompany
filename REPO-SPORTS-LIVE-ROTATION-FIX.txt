REPO SPORTS LIVE — ROTATION / BLACK-SCREEN FIX

SYMPTOM
The new official Repo Sports broadcast reaches full time and then:
- shows end screens repeatedly
- briefly goes black
- reconstructs the finished match again
- sometimes appears permanently stuck at full time

ROOT CAUSE
The live-launch final-whistle RPC could fail during the new persistent player
career upsert. PostgreSQL then rolls the WHOLE completion transaction back.

That means:
- match serial never increments
- shared active clock continues beyond the end
- clients keep seeing the same completed serial

FIX
1. SQL final-whistle function now uses a valid target alias for the career
   ON CONFLICT upsert.
2. Match serial completion remains idempotent.
3. Browser parent stores a pending completed result and retries if the final
   database RPC temporarily fails.
4. Successful host heartbeats also retry a pending completion.
5. A client already on FULL TIME no longer hard-resyncs/reopens the SAME serial
   while waiting for the server to advance.

LEGACY MODE
Legacy Quidditch can remain installed.
This patch does not remove it and does not alter its shared match behaviour.

INSTALL ORDER
1. Run:
   RUN-ONCE-FIX-REPO-SPORTS-LIVE-ROTATION.sql
   in Supabase SQL Editor.

2. Copy:
   index.html
   repo-sports-quidditch-v2-test.html
   into C:\Users\Isaac\Desktop\web2\

3. Overwrite and Ctrl + Shift + R.

If the currently stuck completed match is still displayed after the SQL is run,
hard refresh once. The host will reconstruct it, report the final whistle, the
fixed RPC will advance the serial, and the next match should begin normally.

NO STAT RESET.
NO MATCH RESET IS PERFORMED BY THE SQL ITSELF.
