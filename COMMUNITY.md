# RE-COMP community

The chat launcher opens `repo-community.js` / `repo-community.css` inside the existing messaging dialog. The website and desktop portal share this implementation. Private messages, notifications and call state still use `repo-messaging.js`; the native client still receives `repo-messaging-state`.

Apply the additive `dashboard-community-schema.sql` migration before deploying the Pages code. Roles are stored against verified, immutable account IDs in `community_roles`; there is no client-side role bootstrap. The initial Developers are the verified CatAsthma and Covidpanda accounts. Developers can grant or remove other Developers through Customize → Manage Developer access. An account cannot remove its own role.

Signed-in players with a player profile can enter. There is one initial text channel (`general`), up to 20 text channels, server-checked Developer editing, 4,000-character messages, pagination, search, reactions and deletion by the author or a Developer. Blocking filters public messages and profile access. Community member presence respects appearing offline; private profiles keep their avatar, frame and banner restricted to accepted friends.

There is one community banner and one personal profile banner per account. PNG, JPEG, WebP and animated GIF files are supported up to 1 MiB each. Uploads replace the previous image and stay in the existing D1 database, with no new paid storage service. Binary responses require account authentication. Height, zoom and position are saved separately; only Developers can edit the shared banner. Personal banner writes always use the verified caller's account ID. Avatar and frame appearance comes from the existing avatar system and server-verified equipped shop frame; this feature cannot grant frame ownership.

The single RE-COMP voice channel is open to signed-in players, up to eight simultaneous participants. Entering it uses the existing VoiceHub singleton and the same persistent conservative 800 GB budget as private calls. It is created lazily when someone joins; later entrants join the same channel. The first entrant leaving does not disconnect everybody else. A blocked player cannot join a channel containing the blocking account. Microphone access still requires an explicit join/answer action. Eight-hour sessions, heartbeat expiry, forced upstream cleanup, the monthly cutoff and rolling carryover protection remain in force. See `VOICE.md` for the billing limitations; this is an application cutoff, not a provider-enforced spending cap.

The background uses the site's green glow and CSS particle motion. Motion pauses when the page/client is hidden and follows reduced-motion settings. At narrow widths, channel navigation and the member list open as panels. The top navigation contains only Download, Wibs and Account icons, with accessible names and tooltips. Wibs uses a clean static SVG from the approved animation's original shape.

Member cards are compact, non-modal popovers placed beside the click and kept inside the viewport. They include the existing avatar/frame and personal banner; clicking the username opens the full account profile. Outside clicks and Escape dismiss the card without closing the community. Keyboard activation anchors it beside the selected member. Closing the card, changing account or opening another card invalidates pending profile/banner responses and revokes temporary image URLs.

During a call, green speaker rings appear on voice participants, matching member avatars and the local account row. `repo-voice-activity.js` reads audio energy from existing WebRTC sender/receiver statistics every 100 ms, with a 300 ms release between syllables. Remote tracks are matched to usernames through the SFU's returned receiving mid and trackName. No new microphone capture, recording or server messages are introduced. Muting/deafening suppresses the local indicator; leaving, sign-out, ended tracks and receiver replacement remove the corresponding meters. People outside the call do not receive its audio or activity levels.

Wibs replaces the shared messaging launcher throughout the website and client portal. Opening the closed community page plays the approved logo-to-Wibs wave once, compressed from 4.8 seconds to four seconds; the page loads underneath. Only the animation is visible, with no text or Skip button. Escape, closing or changing account cancels it, and reduced-motion users open the page immediately. The desktop visibility event pauses it while the portal is hidden. Startup and game-specific loaders are unchanged. `repo-wibs-intro.js` and its local mark asset contain the approved animation independently of the localhost preview. Clicking the RE-COMP channel name joins voice; there is no separate Join voice button.

Validation: `node tools/test-community.cjs`, `node tools/test-community-client.cjs`, `node tools/test-community-intro.cjs`, `node tools/test-voice-activity-client.cjs`, the existing messaging and voice tests, game-loader tests, and the relevant desktop media/visibility tests. The activity test uses real local WebRTC peers with synthetic audio to verify identity mapping, silence, mute/deafen and cleanup. Tests use isolated SQLite data, test identities and local browser contexts. No sample people or messages are seeded into production.
